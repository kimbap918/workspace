> 텍스트 기반으로 앱을 기획하는 단계에서 발생하는 무한 로딩, AI 응답 지연, 기획 결과물의 품질 저하 및 구체성 요구에 대한 가이드입니다.

**C. 커뮤니티 템플릿 (Community Templates) — 23개**

> 다른 사용자가 만든 템플릿을 탐색하거나 내 프로젝트로 가져올(Import) 때 발생하는 오류, 빌드 호환성, 상업적 사용 라이선스 및 업로드 정책을 안내합니다.

**D. 프로젝트 및 대시보드 (Dashboard & Project) — 25개**

> 대시보드 내 프로젝트 목록 렌더링 지연, 삭제/복구 정책, 메타데이터(이름/설명) 수정, 팀원 권한 관리 및 URL 발급 오류를 다룹니다.

**E. 에디터 및 미리보기 장애 (Editor & Preview) — 23개**

> 코드 편집기 내의 자동 저장 실패, 우측 미리보기 화면의 화이트 스크린 크래시, 폰트/이미지 404 에러 및 직접 파일 업로드 시 발생하는 문제를 해결합니다.

**F. AI 생성 파이프라인 장애 (Generation Pipeline) — 20개**

> 코드가 생성되는 4단계(Starting, Setting up, Thinking, Generating)에서 멈추는 현상, 자동 복구 실패, 이전 코드로 되돌리기 및 성능 한계를 다룹니다.

**G. 디자인 및 에셋 장애 (Design & Assets) — 16개**

> AI가 렌더링한 이미지(로고, 파비콘 등)의 퀄리티 문제, 다크모드/반응형 레이아웃 파괴, 특정 컬러/폰트 스타일 적용 실패에 대한 디버깅 가이드입니다.

**H. 배포, 호스팅 및 내보내기 (Publish & Export) — 20개**

> 완성된 앱을 게시(Publish)할 때의 빌드 에러, 커스텀 도메인(DNS) 및 SSL 연결 지연, 그리고 소스 코드를 ZIP으로 다운로드할 때의 호환성 문제를 다룹니다.

**I. GitHub 및 백엔드 연동 (GitHub & Backend) — 12개**

> GitHub 저장소 연동 및 Push 권한 에러, 백엔드 Functions 실행 타임아웃, DB 연결 실패 및 외부 API 호출 시의 보안 권장 사항을 안내합니다.

**J. 요금제, 결제 및 크레딧 보상 (Billing, Plans & Credits) — 20개**

> Starter/Builder/Pro 플랜의 기능 차이, 생성 실패 시 크레딧 자동 복구 로직, 환불 규정 및 목적별 최적의 요금제 추천 가이드를 제공합니다.

**K. 프롬프트 엔지니어링 (Prompting Tips) — 16개**

> AI에게 원하는 UI 디자인, 복잡한 비즈니스 로직(DB, 결제 등)을 정확하게 지시하고, 발생한 에러를 수정(디버깅)하도록 유도하는 프롬프트 작성 공식입니다.

**L. 기업 보안 및 시스템 상태 (Security & System) — 11개**

> 프로젝트 자동 백업 정책, 전체 서버 장애 및 접속 지연 여부 파악, SOC2/감사 로그 등 기업용 보안 스펙과 법적(DMCA) 요구 처리 방법을 안내합니다.

## A. 계정 및 인증 장애 (Account & Auth)

### A-1 회원가입 및 약관 동의 장애

#### 1. 회원가입 버튼을 눌러도 아무 반응이 없습니다.
**A:** 브라우저 캐시 충돌이거나 일시적인 네트워크 지연일 수 있습니다. 강력 새로고침(Windows: Ctrl+Shift+R / Mac: Cmd+Shift+R)을 하시거나 브라우저의 시크릿 모드에서 다시 시도해 주세요.

#### 2. 약관 동의를 체크했는데도 가입이 진행되지 않아요.
**A:** 필수 약관 항목이 모두 체크되었는지 확인해 주세요. 만약 광고 차단(AdBlock) 등 브라우저 확장 프로그램을 사용 중이시라면, 해당 스크립트가 가입 버튼의 동작을 막을 수 있으니 잠시 끄고 진행해 보시기를 권장합니다.

#### 3. 이메일 형식이 맞는데 유효하지 않다고 뜹니다.
**A:** 이메일 주소의 앞이나 뒤에 보이지 않는 공백(띄어쓰기)이 포함되어 있을 가능성이 높습니다. 입력 칸의 공백을 지우고 다시 시도해 주세요.

#### 4. 가입 완료 화면이 나오지 않고 계속 로딩 상태입니다.
**A:** 서버 통신 지연으로 화면 전환이 멈춘 상태일 수 있습니다. 페이지를 새로고침하신 후, 가입 시 입력하셨던 이메일과 비밀번호로 로그인을 먼저 시도해 보시기 바랍니다.

#### 5. 이메일 인증 확인 메일이 오지 않습니다.
**A:** 메일 서비스의 스팸 메일함이나 프로모션 탭으로 분류되었는지 확인해 주세요. 메일이 없다면 이메일 주소에 오타가 없는지 확인하신 후 '인증 메일 다시 보내기'를 클릭해 주세요.

### A-2 비밀번호 설정 및 재설정 오류

#### 1. 비밀번호 조건을 충족했는데도 설정이 실패합니다.
**A:** 비밀번호는 최소 8자 이상이어야 하며, 시스템에서 허용하지 않는 일부 특수문자(예: ₩)가 포함되었는지 확인해 주세요. 영문 대소문자, 숫자, 일반적인 특수문자 조합을 권장합니다.

#### 2. 비밀번호 재설정 이메일이 도착하지 않습니다.
**A:** 스팸함을 먼저 확인해 주시고, VibeX에 가입하실 때 사용한 이메일 주소가 정확한지 확인해 주세요. 구글 소셜 로그인으로 가입하신 계정은 VibeX에서 비밀번호를 재설정할 수 없습니다.

#### 3. 재설정 링크가 만료되었다고 나옵니다.
**A:** 보안을 위해 비밀번호 재설정 링크는 발급 후 일정 시간이 지나면 자동으로 만료됩니다. 비밀번호 찾기 페이지에서 링크를 다시 요청하신 후 즉시 진행해 주세요.

#### 4. 새 비밀번호 입력 후에도 로그인에 실패합니다.
**A:** 브라우저의 '비밀번호 자동 완성' 기능 때문에 이전 비밀번호가 덮어씌워져 입력되고 있을 수 있습니다. 자동 입력된 내용을 지우고 새 비밀번호를 직접 타이핑하여 로그인해 보세요.

### A-3 소셜 로그인 연동 장애

#### 1. 구글 로그인 버튼을 누르면 흰 화면이 나옵니다.
**A:** 브라우저의 팝업 차단 기능이 구글 인증 창을 막고 있을 수 있습니다. 주소창 우측의 '팝업 차단 해제' 알림을 클릭하여 팝업을 허용한 뒤 다시 시도해 주세요.

#### 2. 로그인 후 다시 로그인 화면으로 돌아갑니다.
**A:** 쿠키 충돌로 인한 리다이렉트 루프 현상입니다. 브라우저 설정에서 캐시와 쿠키를 삭제하시거나, 시크릿 모드 창을 열어 접속해 보시기 바랍니다.

#### 3. 소셜 로그인 후 계정 정보가 동기화되지 않습니다.
**A:** 소셜 로그인 시 필수 정보(이메일 등) 제공 동의가 누락되었거나 일시적인 API 지연일 수 있습니다. 로그아웃 후 다시 구글 로그인 버튼을 눌러 권한을 허용해 주세요.

### A-4 세션 및 접속 환경 문제

#### 1. 새로고침하면 자동으로 로그아웃됩니다.
**A:** 브라우저의 개인정보 보호 설정에서 '타사 쿠키 차단'이 활성화되어 있으면 로그인 세션이 유지되지 않습니다. 브라우저 설정에서 타사 쿠키를 허용해 주세요.

#### 2. 회사 네트워크에서만 로그인이 실패합니다.
**A:** 사내 방화벽이나 보안 프로그램이 VibeX 서버와의 통신을 차단하고 있을 수 있습니다. 사내 IT 관리자에게 문의하시거나, 개인 네트워크(핫스팟 등)로 접속해 보시기를 권장합니다.

#### 3. 특정 브라우저에서만 접속이 안 됩니다.
**A:** VibeX는 크롬(Chrome) 브라우저 환경에 가장 최적화되어 있습니다. 추적 방지 기능이 강력한 Safari나 Brave 브라우저에서는 일부 로그인 기능이 제한될 수 있습니다.

#### 4. 로그인 상태가 유지되지 않습니다.
**A:** 여러 기기에서 동시에 접속을 시도하거나, VPN 사용 등으로 IP 주소가 자주 변경되는 경우 보안상 시스템이 자동으로 로그아웃 처리를 할 수 있습니다.

### A-5 계정 상태 제한

#### 1. 계정이 잠겼다고 표시됩니다.
**A:** 비밀번호 입력 시도를 연속으로 실패하여 보안상 계정이 일시적으로 잠긴 상태입니다. 30분 후 다시 시도하시거나, 비밀번호 재설정을 통해 잠금을 해제해 주세요.

#### 2. 정책 위반으로 제한되었다고 나옵니다.
**A:** 시스템 모니터링 중 비정상적인 접근 시도나 콘텐츠 정책 위반이 감지되어 계정이 제한되었습니다. 오류라고 생각되시면 support@vibe-x.app으로 문의해 주시기 바랍니다.

#### 3. 로그인 시 접근이 차단되었다고 뜹니다.
**A:** 접속하신 국가나 IP 대역에서 비정상적인 트래픽이 발생하여 시스템 보호 차원에서 접근이 차단된 경우일 수 있습니다. VPN을 사용 중이시라면 끄고 접속해 보세요.

### A-6 계정 정보 변경 및 탈퇴/데이터 파기

#### 1. 이메일 주소를 변경하고 싶습니다.
**A:** 현재 일반 이메일 가입자의 이메일 직접 변경 기능은 지원하지 않습니다. 구글 소셜 로그인 사용자는 구글 계정 자체의 정보를 변경해야 합니다.

#### 2. 탈퇴하면 프로젝트 데이터도 완전히 삭제되나요?
**A:** 네, 계정을 탈퇴하시면 생성하셨던 모든 앱 프로젝트와 관련 데이터가 VibeX 서버에서 즉시 비활성화되며 영구적으로 삭제됩니다.

#### 3. 복구가 가능한가요?
**A:** 아니요, 개인정보 보호 정책에 따라 탈퇴 시 파기된 데이터는 어떠한 경우에도 복구가 불가능합니다. 탈퇴 전 반드시 필요한 코드를 내보내기(Export) 하여 백업해 주세요.

#### 4. 계정을 완전히 삭제(데이터 삭제 요청)하는 방법이 무엇인가요?
**A:** 로그인 후 [설정] > [계정 관리] 메뉴 하단에 있는 '계정 탈퇴' 버튼을 클릭하시면 계정과 모든 데이터가 완전히 삭제됩니다.

#### 5. 로그(작업 기록)는 얼마나 보관되나요?
**A:** 서비스 이용 내역 및 오류 분석을 위한 기본 시스템 로그는 최대 90일간 보관된 후 안전하게 자동 파기됩니다.

#### 6. 개인정보 다운로드가 가능한가요?
**A:** 현재 계정의 모든 정보를 일괄로 다운로드하는 기능은 제공하지 않습니다. 프로젝트의 소스 코드는 에디터에서 개별적으로 다운로드하셔야 합니다.

### A-7 기타 UI 문제

#### 1. 언어 설정이 저장되지 않습니다.
**A:** 브라우저 쿠키에 이전 언어 설정이 고정되어 발생할 수 있습니다. 브라우저 쿠키를 삭제한 후 원하는 언어를 다시 선택해 주세요.

#### 2. 로그아웃 버튼이 작동하지 않습니다.
**A:** 일시적인 프론트엔드 스크립트 오류입니다. 페이지를 강제 새로고침(F5)하신 후 우측 상단의 프로필을 눌러 로그아웃을 다시 시도해 주세요.

#### 3. 설정 페이지가 정상적으로 열리지 않습니다.
**A:** 일시적인 네트워크 지연이거나 서버 점검 중일 수 있습니다. 잠시 후 다시 접속해 보시고, 지속될 경우 캐시를 삭제해 보세요.

#### 4. 계정 정보 화면이 비어있습니다.
**A:** 브라우저의 광고 차단 확장 프로그램이 화면 렌더링을 방해하고 있을 수 있습니다. 확장 프로그램을 끄고 화면을 새로고침해 주세요.

## B. 앱 계획 생성 기능 장애 (App Planning)

### B-1 입력 UI 동작 오류

#### 1. 프롬프트 입력창이 작동하지 않습니다.
**A:** 화면 로딩 중 스크립트가 멈춘 상태일 수 있습니다. 페이지를 새로고침(F5)하여 에디터를 다시 불러와 주세요.

#### 2. 엔터를 눌러도 제출이 되지 않습니다.
**A:** Shift + Enter 조합은 줄바꿈으로 인식됩니다. Enter 키만 누르시거나, 입력창 옆에 있는 '전송' 아이콘을 직접 마우스로 클릭해 보세요.

#### 3. 시작 버튼이 비활성화되어 있습니다.
**A:** 프롬프트에 입력된 텍스트가 너무 짧거나, 오프라인(네트워크 끊김) 상태일 때 버튼이 비활성화됩니다. 인터넷 연결을 확인하고 기획 내용을 조금 더 작성해 보세요.

#### 4. 입력한 텍스트가 사라졌습니다.
**A:** 입력 도중 네트워크가 끊어지거나 페이지를 이동하여 내용이 유실된 경우입니다. 자동 임시 저장이 되지 않은 상태이므로 내용을 다시 입력해 주셔야 합니다.

### B-2 AI 응답 지연 및 중단

#### 1. AI가 계속 thinking 상태입니다.
**A:** 요구하신 앱 구조가 매우 복잡하거나 서버에 접속자가 몰렸을 때 AI의 사고(Thinking) 시간이 길어질 수 있습니다. 1~2분 정도 대기해 주세요.

#### 2. 응답이 중간에 끊겼습니다.
**A:** AI 모델의 최대 출력 글자 수 한도에 도달했거나 API 타임아웃이 발생한 경우입니다. "이어서 계속 써줘"라고 입력하시면 중단된 부분부터 다시 작성합니다.

#### 3. 무한 로딩이 발생합니다.
**A:** 답변을 생성하는 중 네트워크 연결이 불안정해져 화면이 멈춘 상태입니다. 새로고침 후 대화 기록(히스토리)에서 이전 대화를 다시 불러와 주세요.

#### 4. 생성이 멈춘 것 같습니다.
**A:** 3분 이상 화면에 아무런 변화가 없다면 내부 에러로 인해 처리가 중단된 것입니다. "다시 생성해 줘"라고 재요청을 진행해 주세요.

### B-3 기획 결과 품질 문제

#### 1. 결과가 너무 일반적입니다.
**A:** 프롬프트가 너무 짧을 때 발생합니다. 구체적인 타겟 사용자, 주요 컬러, 핵심 기능 등 원하는 방향성을 명확히 적어주시면 훨씬 디테일한 기획안이 나옵니다.

#### 2. 원하는 도메인과 다른 방향으로 나왔습니다.
**A:** AI가 단어의 의미를 다르게 해석한 경우입니다. "이 앱은 쇼핑몰이 아니라, 사내 교육용 앱이야"라고 프롬프트를 통해 명확히 정정해 주세요.

#### 3. 로그인 기능이 포함되지 않았습니다.
**A:** AI가 시각적인 UI 중심으로 먼저 기획을 짠 경우입니다. "반드시 이메일 로그인과 회원가입 기능 명세를 추가해 줘"라고 추가로 요구해 보세요.

#### 4. 모바일 앱을 요청했는데 웹 기준으로 제작됐습니다.
**A:** VibeX는 웹 기반 생성이 기본 설정입니다. "반드시 모바일 화면 비율(Mobile-first)에 맞춘 UI와 터치 상호작용으로 기획해 줘"라고 지시사항에 명시해 주셔야 합니다.

### B-4 결과 확장 요구

#### 1. 화면 목록을 더 구체적으로 받고 싶습니다.
**A:** 프롬프트에 "이 앱에 필요한 전체 페이지 리스트와 각 페이지별 주요 기능을 표(Table) 형태로 정리해 줘"라고 구체적으로 요청해 보세요.

#### 2. 데이터베이스 구조를 포함해 줄 수 있나요?
**A:** 네, 가능합니다. "사용자 정보와 데이터를 저장하기 위한 JSON 형태의 데이터베이스(DB) 스키마를 기획안에 추가해 줘"라고 입력하시면 됩니다.

#### 3. API 목록도 함께 제공되나요?
**A:** 기본 기획에는 생략될 수 있습니다. "클라이언트와 서버가 통신할 REST API 엔드포인트 목록을 정의해 줘"라고 요청하시면 추가로 제공합니다.

#### 4. 일정/마일스톤 계획도 포함할 수 있나요?
**A:** 네, "이 앱을 4주 안에 완성하기 위한 주차별 개발 마일스톤(일정)을 함께 짜줘"라고 입력하시면 단계별 개발 계획을 세워 줍니다.

### B-5 결과 저장/Export 문제

#### 1. 이 계획을 프로젝트로 변환할 수 있나요?
**A:** 네, AI와 기획 대화를 마친 후 화면 우측의 '프로젝트 생성(코딩 시작하기)' 버튼을 누르시면, 해당 기획안을 바탕으로 실제 코드 생성이 시작됩니다.

#### 2. 결과를 PDF로 다운로드할 수 있나요?
**A:** 현재 기획 대화 내용을 즉시 PDF나 외부 문서 파일로 다운로드하는 기능은 지원하지 않습니다. 텍스트를 드래그하여 직접 복사해 주시기 바랍니다.

#### 3. 저장 버튼이 보이지 않습니다.
**A:** 기획 대화는 실시간으로 자동 저장되므로 별도의 저장 버튼이 필요하지 않습니다.

#### 4. 결과가 자동 저장되지 않습니다.
**A:** 대시보드의 대화 히스토리 목록에서 보이지 않는다면 일시적인 동기화 오류일 수 있습니다. 화면을 새로고침해 주세요.

### B-6 컨텍스트 및 모더레이션

#### 1. 같은 질문인데 결과가 매번 다릅니다.
**A:** 생성형 AI의 특성상 동일한 프롬프트라도 생성할 때마다 구조나 어휘가 달라질 수 있습니다. 일관된 결과를 원하시면 프롬프트에 제약 조건(예: "이전 레이아웃을 반드시 유지할 것")을 명시해야 합니다.

#### 2. 이전 대화 내용이 반영되지 않았습니다.
**A:** 대화가 너무 길어지면 AI가 초기에 지시한 내용을 잊어버릴 수 있습니다. "처음에 말했던 다크모드 적용 규칙을 잊지 말고 반영해 줘"라고 다시 한번 상기시켜 주세요.

#### 3. 정책 위반 메시지가 뜹니다.
**A:** 프롬프트 내에 폭력성, 선정성, 불법적인 내용이 감지되어 시스템에 의해 차단된 경우입니다. 가이드라인에 맞게 프롬프트를 수정해 주세요.

## C. 커뮤니티 템플릿 (Community Templates)

### C-1 탐색 및 UI 로딩 오류

#### 1. 템플릿 검색이 되지 않습니다.
**A:** 일시적인 검색 인덱싱 지연일 수 있습니다. 브라우저를 새로고침하신 후 다른 키워드로 다시 검색해 보세요.

#### 2. 카테고리 필터가 작동하지 않습니다.
**A:** UI 스크립트 오류이거나 해당 카테고리에 할당된 템플릿이 없는 상태입니다. '전체' 보기로 초기화한 후 다시 필터를 클릭해 보세요.

#### 3. 썸네일 이미지가 로드되지 않습니다.
**A:** 템플릿 이미지를 제공하는 외부 서버(CDN) 지연 현상입니다. 네트워크 상태를 확인하시고 잠시 후 새로고침해 주세요.

#### 4. 템플릿 목록이 비어 있습니다.
**A:** 적용하신 검색 필터 조건에 맞는 템플릿이 존재하지 않거나, 서버 동기화 지연 중입니다. 필터를 초기화해 보시기 바랍니다.

### C-2 상세 및 미리보기 오류

#### 1. 템플릿 클릭 시 404가 나옵니다.
**A:** 해당 템플릿의 원작자가 템플릿을 삭제했거나, 상태를 비공개(Private)로 전환하여 더 이상 접근할 수 없는 상태입니다.

#### 2. 상세 페이지가 열리지 않습니다.
**A:** 페이지 라우팅 오류입니다. 뒤로 가기를 누른 후 템플릿 카드를 다시 클릭해 보시거나 새로고침해 주세요.

#### 3. 미리보기 권한이 없다고 표시됩니다.
**A:** 해당 템플릿이 특정 플랜(예: Elite 이상) 전용 기능을 포함하고 있어 접근이 제한된 상태일 수 있습니다. 본인의 플랜을 확인해 주세요.

#### 4. 템플릿 설명이 제대로 표시되지 않습니다.
**A:** 원작자가 템플릿 설명을 작성하지 않았거나, 텍스트 렌더링 오류일 수 있습니다. 템플릿 미리보기를 통해 직접 기능을 확인하시는 것을 권장합니다.

### C-3 Import 실패

#### 1. 템플릿은 어떻게 적용하나요? (프로젝트로 가져올 수 없습니다.)
**A:** 마음에 드는 템플릿의 상세 페이지에서 '가져오기(Import)' 버튼을 클릭하시면, 고객님의 워크스페이스에 새 프로젝트로 복사되어 적용됩니다.

#### 2. 가져오기 버튼이 비활성화되어 있습니다.

**A:** 고객님의 계정이 생성할 수 있는 프로젝트 한도(플랜 제한)를 초과했거나, 권한이 없는 템플릿일 경우 버튼이 비활성화됩니다.

#### 3. 가져온 후 일부 파일이 깨졌습니다.

**A:** 템플릿이 과거에 제작되어 현재 빌드 환경과 맞지 않거나 에셋 경로가 누락된 경우입니다. 에디터에서 '코드 재생성'을 시도해 보세요.

#### 4. 템플릿 아이콘이 표시되지 않습니다.

**A:** 원작자가 아이콘(파비콘)을 설정하지 않았거나, 이미지 경로가 유실된 상태입니다. 에디터에서 새 아이콘 생성을 요청해 보세요.

#### 5. 가져온 템플릿을 완전히 내 것으로 만들 수 있나요? (수정은 어디서 하나요?)

**A:** 네, 가져오기를 완료하면 독립적인 복사본이 생성되므로 내 프로젝트가 됩니다. 에디터 화면에 진입하여 프롬프트를 통해 코드를 자유롭게 수정하실 수 있습니다.

### C-4 빌드/호환성 오류

#### 1. 템플릿이 빌드 실패합니다.

**A:** 템플릿에 사용된 외부 패키지가 업데이트되어 현재 VibeX 빌드 환경과 의존성 충돌이 일어난 경우입니다.

#### 2. 실행 시 오류가 발생합니다.

**A:** 에디터 하단의 챗봇 창에 "실행 오류를 고쳐줘"라고 프롬프트를 입력하시면, AI가 호환성 문제를 분석하여 코드를 수정해 줍니다.

#### 3. 의존성 충돌 메시지가 나타납니다.

**A:** 구버전 라이브러리가 사용되었기 때문입니다. 프롬프트에 "package.json의 의존성 버전을 최신으로 업데이트하고 코드를 수정해 줘"라고 지시해 보세요.

### C-5 라이선스 및 플랜 제한

#### 1. 이 템플릿은 무료인가요?

**A:** 네, 커뮤니티에 공개된 템플릿을 내 워크스페이스로 '가져오기' 하는 것 자체는 비용이 들지 않습니다.

#### 2. 사용 시 크레딧이 차감되나요?

**A:** 템플릿을 가져온 후, 본인의 입맛에 맞게 프롬프트를 입력하여 코드를 '수정'하거나 재생성할 때는 본인의 계정 크레딧이 정상적으로 차감됩니다.

#### 3. 폰트/이미지 상업적 사용이 가능한가요?

**A:** 템플릿 원작자가 추가한 커스텀 이미지나 폰트는 저작권이 얽혀있을 수 있습니다. 상업적 서비스 배포를 준비하신다면 본인의 에셋으로 교체하여 사용하시기를 강력히 권장합니다.

#### 4. 특정 플랜에서만 사용 가능한가요?

**A:** 템플릿 가져오기는 모든 플랜에서 가능하지만, 템플릿 내에 '백엔드 기능' 등 상위 플랜 전용 기능이 포함되어 있다면 해당 기능을 지원하는 플랜에서만 완벽하게 작동합니다.

### C-6 업로드 정책

#### 1. 제 템플릿을 커뮤니티에 올릴 수 있나요?

**A:** 네, 프로젝트 설정에서 '공개(Public)' 및 '커뮤니티 공유' 옵션을 활성화하시면 다른 유저들도 볼 수 있는 템플릿으로 등록됩니다.

#### 2. 업로드가 거절되었습니다. 이유가 무엇인가요?

**A:** 프로젝트 내에 폭력성, 선정성, 유명 브랜드 상표권 침해 요소가 포함되어 시스템의 콘텐츠 모더레이션 검수에서 반려된 경우입니다.

#### 3. 업로드 후 수정이 가능한가요?

**A:** 본인의 원본 프로젝트 코드를 수정하시면 커뮤니티 템플릿 내용도 업데이트됩니다. 단, 이미 다른 사용자가 예전 버전으로 복사해간 내역에는 반영되지 않습니다.

## D. 프로젝트 및 대시보드 (Dashboard & Project)

### D-1 목록 렌더링 오류

#### 1. 새 프로젝트는 어떻게 만드나요? (목록이 비어있습니다.)

**A:** 대시보드 우측 상단에 있는 '새 프로젝트(또는 새 앱 만들기)' 버튼을 클릭하시면 됩니다. 만약 프로젝트를 생성했는데도 목록이 비어있다면, 아직 서버 통신이 완료되지 않은 상태일 수 있으니 페이지를 새로고침(F5)해 주세요.

#### 2. 생성 후 목록에 나타나지 않습니다.

**A:** 프로젝트 생성 데이터가 대시보드 목록으로 동기화되는 데 일시적인 지연이 발생한 상태입니다. 브라우저를 새로고침하시면 정상적으로 나타납니다.

#### 3. 다른 기기에서 보이지 않습니다.

**A:** PC와 태블릿 등 기기 간에 동일한 이메일(또는 동일한 소셜 연동 계정)로 로그인되었는지 다시 한번 확인해 주시기 바랍니다.

#### 4. 카드가 로딩만 됩니다.

**A:** 대시보드에 표시될 프로젝트의 미리보기 썸네일을 렌더링하는 중이거나, 네트워크가 일시적으로 불안정한 상태입니다. 잠시 후 새로고침해 주세요.

### D-2 프로젝트 진입 실패

#### 1. 프로젝트 클릭 시 404가 뜹니다.

**A:** 해당 프로젝트가 이미 다른 기기에서 삭제되었거나, 브라우저 캐시에 남아있는 잘못된 링크를 클릭하신 경우입니다. 대시보드로 돌아가 최신 목록을 확인해 주세요.

#### 2. creating 상태에서 멈춰 있습니다.

**A:** 백그라운드에서 프로젝트 환경을 구성하는 도중 타임아웃이 발생한 상태입니다. 계속 멈춰 있다면 해당 프로젝트 카드를 삭제하고 새로 생성해 주시기 바랍니다.

#### 3. 진입하면 바로 튕깁니다.

**A:** 세션이 만료되었거나 브라우저 캐시가 꼬인 상태입니다. 로그아웃 후 다시 로그인하시거나, 시크릿 모드에서 접속해 보세요.

#### 4. 접근 권한이 없다고 표시됩니다.

**A:** 해당 프로젝트가 '비공개(Private)'로 설정되어 있으며, 고객님께서 초대받지 않은 계정으로 로그인하신 경우입니다. 올바른 워크스페이스나 계정인지 확인해 주세요.

### D-3 프로젝트 정보 표시 및 관리 문제

#### 1. 프로젝트 이름이 변경되지 않습니다.

**A:** 프로젝트 이름을 에디터 상단이나 설정에서 변경하신 후, 반드시 Enter 키를 누르거나 빈 공간을 클릭하여 저장을 완료해 주셔야 반영됩니다.

#### 2. 프로젝트 설명(또는 제목)이 저장되지 않습니다.

**A:** 일시적인 네트워크 지연입니다. 텍스트를 입력하신 후 잠시 기다렸다가 다른 메뉴를 클릭하시면 정상적으로 자동 저장됩니다.

#### 3. 최근 수정일이 갱신되지 않습니다.

**A:** 대시보드 목록의 정렬 데이터가 실시간으로 갱신되지 않은 현상입니다. 화면을 새로고침하시면 최신 수정 시간으로 업데이트됩니다.

#### 4. 프로젝트 정보가 다른 기기와 동기화되지 않습니다.

**A:** 로그아웃 후 다시 로그인하여 캐시를 강제로 갱신해 주시면 타 기기에서의 변경 사항이 정상적으로 반영됩니다.

#### 5. 폴더로 관리할 수 있나요?

**A:** 현재 VibeX는 폴더링 기능을 제공하지 않습니다. 대신 프로젝트 이름을 "[쇼핑몰] 메인 화면"처럼 규칙을 정해 작성하시면 관리가 수월합니다.

### D-4 삭제/복구 문제

#### 1. 삭제 절차는 어떻게 되나요?

**A:** 대시보드 목록에서 프로젝트 카드의 우측 상단 점 3개(더보기) 아이콘을 클릭한 후, [삭제(Delete)] 버튼을 누르시면 됩니다.

#### 2. 삭제 버튼이 작동하지 않습니다.

**A:** 브라우저 스크립트가 일시적으로 멈춘 상태입니다. 페이지를 새로고침하신 후 다시 삭제를 시도해 주세요.

#### 3. 삭제 후에도 목록에 남아 있습니다.

**A:** 서버에서는 삭제가 완료되었으나 브라우저 화면에 잔류하는 캐시 현상입니다. F5 키를 눌러 새로고침하시면 목록에서 완전히 사라집니다.

#### 4. 삭제한 프로젝트를 복구할 수 있나요?

**A:** 아니요, 삭제된 프로젝트와 코드는 시스템에서 즉시 영구 파기되므로 어떠한 경우에도 복구가 불가능합니다. 삭제 시 신중해 주시기 바랍니다.

#### 5. 프로젝트를 복제 기능이 있나요?

**A:** 네, 프로젝트 카드의 우측 상단 더보기(점 3개) 메뉴에서 '복제(Duplicate)'를 선택하시면 동일한 상태의 프로젝트가 복사본으로 생성됩니다.

### D-5 협업 및 권한

#### 1. 팀원과 프로젝트를 공유할 수 있나요? (초대 기능이 지원되나요?)

**A:** 네, 계정 설정에서 팀 워크스페이스를 생성한 후 이메일로 팀원을 초대하면 프로젝트를 함께 공유하고 작업할 수 있습니다.

#### 2. 읽기 전용으로 표시됩니다.

**A:** 워크스페이스 관리자가 고객님을 '편집자'가 아닌 '뷰어(Viewer)' 권한으로 초대했거나, 공유받은 템플릿의 소유권이 본인에게 없을 때 나타납니다.

#### 3. 소유자를 변경할 수 있나요?

**A:** 현재 특정 프로젝트의 소유권(Owner) 자체를 다른 계정으로 완전히 이전하는 기능은 지원하지 않습니다.

### D-6 URL 발급 실패

#### 1. preview_url이 null입니다.

**A:** 프로젝트 코드가 아직 생성 중이거나, 빌드 프로세스 중에 에러가 발생하여 미리보기 서버가 띄워지지 않은 상태입니다. 생성이 100% 완료될 때까지 대기해 주세요.

#### 2. published_url이 생성되지 않았습니다.

**A:** 프로젝트를 실제로 외부 서버에 '배포(Publish)' 완료해야만 접근 가능한 URL이 발급됩니다. 아직 게시 버튼을 누르지 않으셨다면 발급되지 않습니다.

#### 3. URL을 눌렀는데 열리지 않습니다.

**A:** 브라우저의 팝업 차단 기능이 새 창 열기를 막고 있을 수 있습니다. 팝업 차단을 해제하거나 URL을 복사하여 새 탭에 직접 붙여넣어 보세요.

#### 4. 배포했는데 링크가 없습니다.

**A:** 배포 과정이 100% 완료되지 않았거나 진행 중 오류가 발생한 것입니다. 배포 상태가 '성공'으로 바뀔 때까지 잠시 기다려 주세요.

## E. 에디터 및 미리보기 장애 (Editor & Preview)

### E-1 에디터 로딩 및 파일 트리 오류

#### 1. 에디터가 무한 로딩 상태입니다.

**A:** 에디터 환경을 불러오는 중 네트워크 연결이 불안정해진 상태입니다. 페이지를 강제로 새로고침(Windows: Ctrl+Shift+R, Mac: Cmd+Shift+R) 하여 다시 진입해 주세요.

#### 2. 파일을 클릭해도 코드가 열리지 않습니다.

**A:** 일시적인 프론트엔드 렌더링 오류입니다. 다른 파일을 먼저 클릭했다가 다시 원하시는 파일을 클릭해 보시기 바랍니다.

#### 3. 워크스페이스가 비어 있습니다.

**A:** 프롬프트 입력 단계에서 생성이 실패했거나 아무 내용도 없는 빈 프로젝트인 경우입니다. 새 프롬프트를 입력하여 생성을 시작해 주세요.

#### 4. 파일 구조를 변경할 수 있나요?

**A:** 현재 AI가 구성한 프레임워크 파일 트리(폴더 구조)를 사용자가 직접 폴더를 만들거나 드래그하여 임의로 변경하는 기능은 제한적으로만 지원됩니다.

### E-2 저장 및 동기화 장애

#### 1. 코드를 수정했는데 저장되지 않습니다.

**A:** 코드를 직접 수동으로 편집(Manual Edit)하던 중 인터넷 연결이 잠시 끊겨 서버로 변경 사항이 전송되지 않은 경우입니다.

#### 2. 새로고침하면 수정 내용이 사라집니다.

**A:** 작성한 코드가 서버에 안전하게 자동 저장(Auto-save)되기 전에 새로고침을 누르신 경우입니다. 편집 후 우측 미리보기 화면이 갱신되는 것을 확인한 뒤 새로고침을 해주세요.

#### 3. 자동 저장 기능이 있나요?

**A:** 네, VibeX 에디터는 기본적으로 코드의 변경 사항이 감지될 때마다 백그라운드에서 실시간 자동 저장을 수행합니다.

### E-3 렌더링 크래시

#### 1. 미리보기가 흰 화면입니다.

**A:** AI가 생성한 React/Vue 코드 내부에 치명적인 렌더링 에러가 발생하여 화면이 멈춘 상태입니다. 에디터 하단의 챗봇에게 "미리보기가 흰 화면이야, 렌더링 에러를 고쳐줘"라고 지시하세요.

#### 2. 모바일 반응형 레이아웃이 깨집니다.

**A:** 최초 프롬프트에 모바일 최적화 지시를 명확히 하지 않아 PC 기준으로만 생성된 경우입니다. "현재 화면을 모바일에서도 예쁘게 보이도록 반응형(Tailwind sm, md 등) 처리를 추가해 줘"라고 다시 명령해 주세요.

#### 3. 새로고침할 때마다 상태가 초기화됩니다.

**A:** 브라우저 새로고침 시 앱 내부의 상태(State, 예: 장바구니 담김, 로그인 상태)가 초기화되는 것은 웹 애플리케이션의 정상적인 작동 방식입니다.

#### 4. 특정 컴포넌트만 렌더링되지 않습니다.

**A:** 해당 컴포넌트 내부의 로직에 오류가 있거나, 조건부 렌더링(Conditional Rendering)에서 데이터가 비어있어 화면에 그리지 못한 경우입니다.

### E-4 네트워크 및 에셋 오류

#### 1. 이미지가 404 에러로 표시됩니다.

**A:** 이미지 파일의 경로가 잘못 지정되었거나, 외부 이미지 호스팅 서버에서 해당 이미지가 삭제된 경우 엑스박스(404)로 표시됩니다.

#### 2. 폰트가 로드되지 않습니다.

**A:** 구글 폰트 등 외부 폰트 링크에 오타가 있거나 폰트 서버의 지연 문제입니다. 코드 내의 `import` 또는 `<link>` 태그 경로를 확인해 달라고 AI에게 지시해 보세요.

#### 3. 외부 API 호출이 CORS로 차단됩니다.

**A:** 브라우저의 미리보기 환경에서는 보안 정책(CORS)으로 인해 외부 API를 직접 호출하는 것이 막히는 경우가 많습니다. 실제 배포(Publish)를 완료한 후 테스트해 보시기를 권장합니다.

#### 4. 네트워크 요청이 실패했다고 나옵니다.

**A:** 프론트엔드 코드에서 요청하는 API 주소가 잘못되었거나 데이터 응답 구조가 맞지 않아 발생하는 문제입니다. 에러 메시지를 복사해 AI에게 디버깅을 요청하세요.

### E-5 UI 부가기능 및 탭 사용법

#### 1. 코드 탭과 데이터 탭의 차이는 무엇인가요?

**A:** '코드' 탭은 실제 화면을 구성하는 프론트엔드 소스 코드를 편집하는 곳이며, '데이터' 탭은 앱에서 사용할 샘플 JSON 데이터나 백엔드 DB 구조를 확인하고 관리하는 곳입니다.

#### 2. 대시보드 탭은 무엇인가요?

**A:** 프로젝트의 배포 상태 확인, 환경 변수 설정, 도메인 연결 등 앱 운영과 관련된 전반적인 관리 설정을 수행하는 메뉴입니다.

#### 3. 로그는 어디서 확인하나요?

**A:** 에디터 화면 우측 하단의 '콘솔(Console)' 버튼을 누르시면, 빌드 과정의 에러나 런타임에 발생하는 자바스크립트 로그를 실시간으로 확인하실 수 있습니다.

#### 4. 다크모드/테마 변경이 반영되지 않습니다.

**A:** Tailwind CSS 등의 설정 파일에 다크모드 설정이 누락되었기 때문입니다. AI에게 "시스템 테마에 맞게 다크모드가 즉시 적용되도록 설정 코드를 추가해 줘"라고 요청하세요.

#### 5. 키보드 단축키 충돌 및 코드 자동 정렬이 작동하지 않습니다.

**A:** 브라우저 자체 단축키와 겹치거나 포맷터(Prettier) 스크립트 에러일 수 있습니다. 직접 코드를 드래그하여 우클릭 메뉴의 '코드 정렬'을 시도해 보세요.

### E-6 파일 업로드 및 경로 오류

#### 1. 이미지 업로드가 되지 않습니다.

**A:** 일시적인 네트워크 오류이거나 지원하지 않는 파일 형식일 수 있습니다. 브라우저를 새로고침하신 후 이미지를 다시 드래그 앤 드롭해 보세요.

#### 2. 파일 업로드 용량 제한이 있나요?

**A:** 네, 프로젝트 최적화와 서버 안정성을 위해 1회 업로드 가능한 이미지 파일 용량은 보통 5MB 이하로 제한됩니다. 이미지 크기를 줄인 후 업로드해 주세요.

#### 3. 특정 확장자는 업로드가 안 되나요?

**A:** 보안상의 이유로 실행 파일(.exe, .sh) 등은 차단되며, 웹 렌더링에 적합한 표준 이미지(jpg, png, svg, webp) 형식의 업로드만 지원합니다.

## F. AI 생성 파이프라인 장애 (Generation Pipeline)

### F-1 단계별 무한 대기

#### 1. Starting 단계에서 멈췄습니다.

**A:** 프로젝트 초기화 공간을 할당하는 중 서버에 부하가 발생한 상태입니다. 잠시 후 페이지를 새로고침(F5)하여 재시도해 주세요.

#### 2. Setting up project에서 진행되지 않습니다.

**A:** 프로젝트에 필요한 리액트나 뷰 패키지(Dependencies)를 서버에 설치하는 과정에서 타임아웃이 발생했습니다. 생성을 취소하고 다시 버튼을 눌러주세요.

#### 3. Thinking 상태가 10분째 유지됩니다.

**A:** 요구하신 앱 구조가 매우 방대하여 AI가 구조를 설계(Thinking)하는 데 시간이 걸리거나, 일시적인 모델 API 응답 지연입니다. 새로고침 후 기다려 주시기 바랍니다.

#### 4. Generating image 단계에서 정지했습니다.

**A:** 로고나 3D 에셋을 렌더링하는 전용 이미지 서버의 트래픽이 지연되고 있는 상태입니다. 백그라운드에서는 진행 중일 수 있으니 창을 닫지 말고 조금 더 대기해 주세요.

### F-2 생성 상태 표시 이상 또는 화면 동기화 문제

#### 1. 생성이 끝난 것 같은데 계속 로딩으로 표시됩니다.

**A:** 백엔드에서는 생성이 완료되었으나, 브라우저 화면의 진행 바(UI)가 최신 상태로 업데이트되지 못한 경우입니다. 새로고침하시면 정상 완료 상태로 보입니다.

#### 2. 이미 결과가 보이는데 상단에는 “생성 중”이라고 나옵니다.

**A:** 코드는 완료되었으나 백그라운드에서 썸네일이나 추가 에셋을 계속 생성하고 있는 과정일 수 있습니다. 화면 조작은 가능하므로 그대로 사용하셔도 무방합니다.

#### 3. 진행 단계가 다시 처음으로 돌아간 것처럼 보입니다.

**A:** 생성 중 에러가 감지되어 AI가 스스로 코드를 수정하고 처음부터 다시 빌드를 시도(Auto-fix)하는 정상적인 복구 로직이 작동 중인 것입니다.

#### 4. 화면이 멈춘 것 같은데 새로고침하면 상태가 달라집니다.

**A:** 브라우저와의 실시간 소켓 통신이 일시적으로 끊겼으나 서버 작업은 정상 진행된 경우입니다. 작업은 유실되지 않으니 안심하셔도 됩니다.

### F-3 로그 및 에셋 반환 누락

#### 1. uuid는 생성되었는데 image_url이 없습니다.

**A:** 이미지 렌더링 요청은 접수(uuid 발급)되었으나, 이미지 생성 서버의 오류로 최종 결과물(URL)을 받지 못한 상태입니다. 에디터에서 해당 에셋의 재생성을 요청해 주세요.

#### 2. output_images가 비어 있습니다.

**A:** 사용자의 프롬프트에 이미지 생성을 지시할 만한 단서가 없었거나, AI가 텍스트 코드만으로 충분하다고 판단하여 이미지 생성 프로세스를 건너뛴 것입니다.

#### 3. 로그가 중간에 끊겼습니다.

**A:** AI가 답변을 출력(Streaming)하는 도중 네트워크 연결이 불안정해진 경우입니다. 챗봇 창에 "코드가 끊겼어. 방금 쓰던 부분부터 이어서 작성해 줘"라고 입력하세요.

#### 4. 특정 에셋만 생성되지 않았습니다.

**A:** 히어로 이미지나 로고 등 여러 에셋을 동시에 요청했을 때 일부 에셋 렌더링이 타임아웃된 경우입니다. 누락된 에셋만 콕 집어서 다시 만들어달라고 프롬프트를 작성해 주세요.

### F-4 자동 복구 및 재시도 오류

#### 1. error_auto_fix가 반복되지만 해결되지 않습니다.

**A:** AI가 감지한 에러의 충돌이 너무 심각하여 스스로 해결하지 못하고 무한 루프에 빠진 상태입니다. 생성을 강제로 중단하고, 에디터 상단의 '코드 초기화'를 누른 뒤 다시 시작하는 것이 빠릅니다.

#### 2. 재시도했더니 이전 결과가 사라졌습니다.

**A:** '재생성'은 기본적으로 현재 버전을 완전히 새로운 코드로 덮어쓰는 과정입니다. 덮어쓰기 전의 결과물을 원하신다면 되돌리기 기능을 사용해야 합니다.

#### 3. 되돌리기 기능이 작동하지 않습니다.

**A:** 코드 수정 이력(History)이 시스템 메모리 한도를 초과하여 가장 오래된 버전이 지워졌거나, 동기화 오류입니다.

#### 4. 재생성 버튼이 어디에 있나요?

**A:** 에디터 화면 우측 상단이나, 좌측 챗봇 대화 기록(히스토리) 블록의 우측에 있는 새로고침 모양의 아이콘을 클릭하시면 재생성을 시작할 수 있습니다.

### F-5 성능 및 모델 한계

#### 1. 특정 시간대에 생성이 매우 느립니다.

**A:** 사용자 접속이 집중되는 특정 시간대(예: 심야 또는 특정 국가의 업무 시간)에는 AI API 호출 큐(Queue) 대기열이 길어져 생성 속도가 일시적으로 느려질 수 있습니다.

#### 2. 같은 프롬프트인데 결과가 달라집니다.

**A:** 생성형 AI 모델의 창의성(Temperature) 설정에 의해, 완전히 동일한 문장이라도 매번 미세하게 다른 코드 구조와 디자인 결과물을 도출합니다.

#### 3. 모델을 변경할 수 있나요?

**A:** 현재 VibeX는 품질이 가장 검증된 단일 AI 모델(예: Claude 최신 버전)을 기본으로 고정하여 제공하므로, 사용자가 임의로 다른 회사의 모델로 변경할 수는 없습니다.

#### 4. 생성 속도를 빠르게 할 방법이 있나요?

**A:** 프롬프트를 한 번에 수천 자씩 입력하여 복잡한 전체 앱을 요구하기보다는, "먼저 로그인 화면만 만들어줘" -> "그다음 장바구니 기능을 추가해 줘"처럼 단계별로 잘라서 요청하시면 훨씬 빠르고 정확한 결과를 얻을 수 있습니다.

## G. 디자인 및 에셋 장애 (Design & Assets)

### G-1 이미지 퀄리티 문제

#### 1. 로고 텍스트가 틀렸습니다.

**A:** 현재 AI 이미지 생성 모델의 한계로 인해 이미지 내의 텍스트 스펠링이 부정확하게 렌더링될 수 있습니다. 이 경우 챗봇에게 "로고 이미지에서 텍스트를 완전히 빼고 심볼만 남겨줘"라고 지시하시거나, 직접 제작한 로고 이미지를 업로드하여 교체하시는 것을 권장합니다.

#### 2. 이미지 비율이 깨졌습니다.

**A:** AI가 컨테이너(박스) 크기를 무시하고 고정된 비율로 이미지를 삽입했을 때 발생합니다. 챗봇에게 "이미지가 잘리지 않게 `object-cover` 속성을 적용해 주고 비율을 맞춰줘"라고 요청해 보세요.

#### 3. 필요 없는 에셋이 생성되었습니다.

**A:** AI가 프롬프트를 해석하는 과정에서 문맥상 필요하다고 오해하여 추가 에셋(예: 게임 블록 이미지 등)을 생성한 경우입니다. "이 페이지에서는 로고를 제외한 모든 AI 생성 이미지를 지워줘"라고 명확히 지시하세요.

#### 4. 이미지 해상도가 낮습니다.

**A:** 웹 페이지 로딩 속도 최적화를 위해 기본적으로 압축된 해상도의 이미지가 제공됩니다. 더 선명한 이미지가 필요하시다면 "이 부분의 히어로 이미지는 고해상도(High-resolution) 품질로 다시 생성해 줘"라고 요청하시기 바랍니다.

### G-2 스타일 적용 실패

#### 1. 요청한 디자인 테마가 반영되지 않았습니다.

**A:** 추상적인 테마 단어(예: 모던한, 예쁜)는 AI가 다르게 해석할 수 있습니다. "여백이 넓은 애플 스타일의 미니멀리즘 테마로 완전히 바꿔줘"처럼 명확한 비교 대상을 제공해 주시면 훨씬 잘 반영됩니다.

#### 2. 컬러 팔레트가 적용되지 않았습니다.

**A:** Tailwind CSS 등에서 기본 색상명이 충돌했기 때문입니다. 프롬프트에 "주요 배경색은 반드시 `#1E1E1E`, 포인트 버튼 색상은 `#FF5733` HEX 코드를 하드코딩해서 적용해 줘"라고 명시해 보세요.

#### 3. 한글 폰트가 깨집니다.

**A:** AI가 한글 폰트를 지원하지 않는 글로벌 기본 폰트(Inter 등)를 강제 적용했을 때 발생합니다. "구글 폰트에서 'Noto Sans KR' 또는 'Pretendard'를 `import`하여 전체 한글 폰트 깨짐을 고쳐줘"라고 지시해 주시기 바랍니다.

#### 4. 폰트 스타일이 다르게 나옵니다.

**A:** 글씨 굵기(Weight)나 자간(Tracking) 설정이 누락된 경우입니다. "제목은 `font-bold` 및 `tracking-tight`로 적용해서 더 무겁고 세련되게 만들어줘"라고 세부 스타일 속성을 콕 집어 요청하세요.

### G-3 반응형 및 상호작용 오류

#### 1. 모바일에서 레이아웃이 깨집니다.

**A:** PC 화면 기준으로만 코드가 작성된 상태입니다. "Tailwind의 반응형 접두사(`sm:`, `md:`, `lg:`)를 사용하여 모바일 화면(폭 768px 이하)에서는 요소들이 가로가 아닌 세로(컬럼)로 배치되게 수정해 줘"라고 지시하세요.

#### 2. 애니메이션이 버벅입니다.

**A:** 자바스크립트로 무거운 애니메이션을 처리했거나 너무 많은 요소가 동시에 움직일 때 발생합니다. "버벅임을 줄이게 JS 애니메이션 대신 CSS `transform`과 `transition`만을 사용해서 가볍게 바꿔줘"라고 요청하세요.

#### 3. 다크/라이트 모드가 동시에 구현되지 않습니다.

**A:** 테마 상태(State)를 관리하는 로직이 빠져있습니다. "사용자의 OS 시스템 설정에 따라 다크모드와 라이트모드가 전환되도록 `dark:` 클래스 속성들을 추가해 줘"라고 입력하시면 해결됩니다.

#### 4. 버튼 클릭 이벤트가 동작하지 않습니다.

**A:** UI 껍데기만 만들어지고 자바스크립트의 `onClick` 이벤트 핸들러가 연결되지 않은 상태입니다. "이 버튼을 눌렀을 때 특정 모달(창)이 열리는 상태 변경 로직을 덧붙여 줘"라고 기능 작동을 별도로 요구해야 합니다.

### G-4 에셋 관리 한계

#### 1. 에셋을 다운로드할 수 있나요?

**A:** 현재 특정 이미지만 우클릭하여 별도로 다운로드하는 기능은 지원되지 않습니다. 전체 코드를 ZIP으로 내보내기 하시면, 그 안에 포함된 `public` 또는 `assets` 폴더에서 원본 이미지를 찾으실 수 있습니다.

#### 2. 생성된 이미지를 교체할 수 있나요?

**A:** 네, 에디터의 파일 트리 메뉴에서 내 컴퓨터에 있는 이미지를 직접 업로드하신 후, 코드 내의 기존 이미지 경로(`src="..."`)를 방금 올린 파일의 이름으로 변경해 주시면 됩니다.

#### 3. 프로젝트 간 에셋 재사용이 가능한가요?

**A:** 현재 다른 프로젝트에서 생성된 에셋(이미지 등)을 또 다른 프로젝트로 바로 가져오는 공통 보관함 기능은 제공하지 않습니다. 원본을 다운로드 후 새 프로젝트에 다시 업로드해 주셔야 합니다.

#### 4. 에셋을 삭제할 수 있나요?

**A:** 네, 에디터 좌측의 파일 트리에서 불필요한 이미지 파일을 우클릭하여 '삭제'하실 수 있습니다. 단, 코드가 해당 이미지를 여전히 참조하고 있다면 에러가 발생할 수 있으니 코드 내의 `<img>` 태그도 함께 지워주셔야 합니다.

## H. 배포, 호스팅 및 내보내기 (Publish & Export)

### H-1 배포 시작 및 실패 오류

#### 1. 배포 절차를 알려주세요.

**A:** 에디터 우측 상단에 있는 '게시(또는 Publish)' 버튼을 누르시면 현재 저장된 코드가 VibeX의 호스팅 서버로 빌드 및 업로드되며, 전 세계 어디서든 접속할 수 있는 웹 주소(URL)가 발급됩니다.

#### 2. 게시 버튼이 눌리지 않습니다.

**A:** 코드가 완전히 저장되지 않았거나, 현재 백그라운드에서 AI가 코드를 생성 중인 경우 게시 버튼이 비활성화됩니다. 생성이 100% 완료된 후 다시 확인해 주세요.

#### 3. 게시를 눌렀는데 아무 반응이 없습니다. (배포 중 멈춤)

**A:** 서버 통신 지연입니다. 배포 요청 큐(Queue)에 대기 중일 수 있으니 약 1~2분 정도 기다려 보시고, 계속 반응이 없다면 페이지를 새로고침하신 후 다시 눌러주세요.

#### 4. 배포 중 오류가 발생했다고 표시됩니다.

**A:** 런타임 환경에서는 보이지 않던 엄격한 빌드 에러(타입스크립트 에러, 패키지 미스매치 등)가 발생한 경우입니다. 에러 로그를 복사해 AI에게 "빌드 에러가 났어, 이 로그를 보고 고쳐줘"라고 요청하세요.

### H-2 배포 결과 접근 오류

#### 1. 배포 URL이 404입니다.

**A:** 배포는 완료되었으나 전 세계 서버망(CDN)에 데이터가 전파(Propagation)되는 데 약간의 지연이 발생한 상태입니다. 1~3분 정도 기다리신 후 브라우저 캐시를 지우고 다시 접속해 보세요.

#### 2. 미리보기와 배포 화면이 다릅니다.

**A:** 배포 시점의 코드와 현재 미리보기 코드가 다릅니다. 에디터에서 마지막으로 코드를 수정한 이후 '게시(Publish)' 버튼을 눌러 새 버전으로 덮어써 주셔야 실제 배포 화면에 반영됩니다.

#### 3. 배포 후 수정하면 자동 반영되나요? (변경 사항이 반영되지 않습니다.)

**A:** 아니요, 에디터에서 코드를 수정하더라도 라이브 서버에 자동으로 반영되지 않습니다. 수정이 끝난 후 반드시 '게시(Publish)' 버튼을 다시 눌러주셔야 업데이트됩니다.

#### 4. published_version이 갱신되지 않습니다.

**A:** 배포 처리가 지연되고 있거나, 기존 코드와 완전히 동일하여 새로운 버전으로 인식되지 않은 경우입니다. 코드에 미세한 수정(주석 추가 등)을 거친 후 다시 배포해 보세요.

### H-3 도메인 및 SSL 장애

#### 1. 커스텀 도메인 연결 설정은 어떻게 하나요?

**A:** [대시보드] > [도메인 설정] 메뉴에서 고객님이 소유한 도메인(예: myapp.com)을 입력하시면, 제공되는 A 레코드 또는 CNAME 값을 고객님의 도메인 구매처(가비아, 후이즈 등) DNS 설정에 등록하시면 됩니다.

#### 2. 도메인 연결이 실패합니다.

**A:** DNS 설정(A 레코드 등)을 변경한 후 전 세계 인터넷망에 이 정보가 전파되기까지 최대 24~48시간이 소요될 수 있습니다. 설정값이 정확하다면 시간을 두고 기다려 주셔야 합니다.

#### 3. SSL(HTTPS) 발급이 안 되는데 자동 설정인가요?

**A:** 네, 도메인 연결이 정상적으로 완료되면 VibeX에서 자동으로 SSL 인증서를 발급 및 적용해 드립니다. 단, 도메인 연결 직후에는 인증서 발급까지 1~2시간 정도 소요되어 '주의 요함'이 뜰 수 있습니다.

#### 4. www 리다이렉트 설정이 필요합니다.

**A:** `www.myapp.com`과 `myapp.com`을 동시에 지원하려면 DNS 설정에서 루트 도메인과 www 서브 도메인을 둘 다 등록해 주셔야 원활한 리다이렉트가 이루어집니다.

### H-4 외부 호스팅 연동 및 ZIP 내보내기

#### 1. ZIP으로 전체 코드를 다운로드/내보낼 수 있나요?

**A:** 네, 에디터 우측 상단의 내보내기 아이콘을 클릭하여 'ZIP으로 다운로드'를 선택하시면 모든 소스 코드와 에셋 파일이 압축된 형태로 로컬 PC에 저장됩니다.

#### 2. 로컬에서 실행하면 빌드가 실패합니다. (Node 버전/의존성 에러가 발생합니다.)

**A:** 고객님의 PC에 설치된 Node.js 버전이 코드가 요구하는 버전과 다르기 때문일 수 있습니다. 다운로드하신 프로젝트 폴더 터미널에서 `npm install`을 새로 실행하시고 `npm run dev`를 구동해 주세요.

#### 3. Vercel에 배포할 수 있나요?

**A:** VibeX 내에서 버튼 한 번으로 Vercel에 직접 배포하는 전용 연동은 지원하지 않습니다. 대신 코드를 GitHub로 내보내기(Push) 하신 후, 해당 GitHub 저장소를 Vercel에 연결하여 배포하실 수 있습니다.

#### 4. 배포 URL에 비밀번호를 걸 수 있나요?

**A:** 현재 VibeX 자체 배포 링크(`stg.vibe-x.app/...`)에 접속 비밀번호(Password Protect)를 걸어두는 기능은 보안 규정상 내부 테스트 중이며 아직 공식적으로 지원하지 않습니다.

#### 5. OG 이미지가 공유 시 표시되지 않습니다.

**A:** 카카오톡이나 슬랙 캐시 서버가 이전 정보를 기억하고 있기 때문입니다. 소스 코드의 `<meta property="og:image" ...>` 경로가 정상인지 확인하시고, 각 서비스의 공유 디버거 툴을 이용해 캐시를 초기화해 보세요.

### H-5 환경 변수 및 API 오류

#### 1. 환경변수가 적용되지 않습니다.

**A:** VibeX 설정 탭에 등록한 환경변수 키 이름이 코드 내부에서 호출하는 키 이름(`process.env.VITE_API_KEY` 등)과 정확히 일치하는지 대소문자를 다시 한번 확인해 주시기 바랍니다.

#### 2. 배포 후 API 호출이 실패합니다. (CORS 에러가 발생합니다.)

**A:** 호출하시려는 외부 API 서버가 VibeX의 배포 도메인 주소를 화이트리스트(허용 목록)에 등록하지 않아서 브라우저 보안 정책에 차단된 것입니다. 외부 API 제공자의 CORS 설정을 확인해야 합니다.

#### 3. 정적 파일이 404로 표시됩니다.

**A:** 에디터에 직접 업로드한 이미지나 폰트 파일이 빌드 과정에서 `public` 폴더나 올바른 경로로 매핑되지 않은 경우입니다. "에셋의 절대 경로 위치를 다시 확인해서 수정해 줘"라고 AI에게 요청하세요.

## I. GitHub 및 백엔드 연동 (GitHub & Backend)

### I-1 GitHub OAuth 및 Repo 생성 실패

#### 1. GitHub 연동 버튼이 보이지 않습니다.

**A:** GitHub 연동(GitHub Integration)은 **Builder 플랜($50/월) 이상**부터 지원하는 기능입니다. 현재 고객님의 요금제가 Free 또는 Starter 플랜인지 확인해 주시기 바랍니다.

#### 2. 권한 승인에서 실패합니다.

**A:** 브라우저 팝업이 차단되었거나, 이전 인증 토큰이 꼬인 상태입니다. 브라우저 설정에서 VibeX에 대한 쿠키를 삭제하시고 GitHub에서 VibeX 앱 권한을 해제한 뒤 처음부터 다시 연동해 보세요.

#### 3. private repo를 생성할 수 있나요?

**A:** 네, GitHub 계정 연동 시 적절한 권한(Scope)을 허용해 주셨다면, VibeX에서 GitHub로 코드를 내보낼 때 공개(Public) 또는 비공개(Private) 저장소 형식을 직접 선택하실 수 있습니다.

#### 4. repo 생성이 완료되지 않았습니다.

**A:** 동명(같은 이름)의 Repository가 이미 고객님의 GitHub에 존재하거나 특수문자가 포함된 이름이라 거절당한 경우입니다. 프로젝트 이름을 영소문자와 하이픈(-) 조합으로 변경하여 다시 시도해 주세요.

### I-2 Push/브랜치 문제

#### 1. push 권한 에러가 발생합니다.

**A:** VibeX와 GitHub 간에 맺은 보안 인증 토큰이 만료된 상태입니다. VibeX 설정에서 GitHub 연동을 해제(Disconnect)하신 후 다시 연결(Connect)하여 권한을 갱신해 주시기 바랍니다.

#### 2. 기존 repo와 충돌이 발생했습니다.

**A:** VibeX에서 코드를 내보내려는데, 기존 GitHub 저장소에 VibeX가 모르는 다른 변경 사항(Commit)이 섞여 있어 강제 덮어쓰기가 거부된 경우입니다. 빈 Repository를 새로 파서 연결하는 것을 권장합니다.

#### 3. 브랜치를 분리할 수 있나요? (PR 워크플로우가 지원되나요?)

**A:** 현재 VibeX 내부에서 `main` 브랜치 외에 다른 개발 브랜치(`dev`, `feature` 등)를 생성하거나 PR(Pull Request) 워크플로우를 진행하는 고급 깃(Git) 조작은 지원하지 않습니다.

### I-3 Backend Functions 오류

#### 1. 백엔드 함수가 실행되지 않습니다. (타임아웃됩니다.)

**A:** 백엔드 기능(Backend Functions)은 서버에서 실행되는 로직이므로 외부 API를 과도하게 호출하거나 무한 루프가 돌 경우 타임아웃(Timeout) 처리됩니다. 코드를 경량화해 보시기 바랍니다.

#### 2. DB 연결이 실패합니다.

**A:** MongoDB나 Supabase 등 외부 데이터베이스 연결 시, 호스트 주소, 포트, 비밀번호 등의 인증 정보가 잘못되었거나 해당 DB 서버에서 VibeX의 IP를 차단하고 있을 수 있습니다. 환경변수 값을 확인해 주세요.

#### 3. 결제 모듈을 붙일 수 있나요?

**A:** 네, Stripe나 포트원(Portone) 등 외부 결제 API를 백엔드 Functions를 통해 호출하여 구현하실 수 있습니다. 단, 실제 상용 결제를 붙이기 전 테스트 모드로 충분히 검증하시기 바랍니다.

### I-4 API 보안 및 레이트리밋

#### 1. API 호출 제한(쿼터 초과)이 있나요?

**A:** 네, 남용을 방지하기 위해 생성된 프로젝트가 단시간에 과도한 트래픽(DDoS 등)을 유발하거나 외부 API를 비정상적으로 호출할 경우, 자체적인 레이트 리밋(Rate Limit)에 의해 일시 차단될 수 있습니다.

#### 2. Secret을 프론트에 넣어도 되나요? (API 키 관리 방법이 무엇인가요?)

**A:** **절대로 안 됩니다.** OpenAI API 키 등 외부에 노출되면 과금이 발생할 수 있는 시크릿 키는 절대 프론트엔드 코드에 직접 입력하지 마세요. 반드시 [대시보드] > [환경 변수(.env)] 메뉴에 안전하게 저장하여 백엔드에서만 참조하도록 구성해야 합니다.

## J. 요금제, 결제 및 크레딧 보상 (Billing, Plans & Credits)

### J-1 플랜 스펙 혼동

#### 1. 어떤 플랜을 선택해야 하나요? (플랜별 차이가 무엇인가요?)

**A:** 가벼운 프로젝트를 원하시면 무제한 앱 생성과 인앱 편집이 가능한 **Starter 플랜(월 10만 크레딧)** 이 적합합니다. 상용 서비스를 준비하신다면 도메인 연결과 백엔드 기능이 추가된 **Builder 플랜(월 25만 크레딧)** 을 권장하며, 대량의 생성이 필요하시면 **Pro 또는 Elite 플랜** 을 선택하시면 됩니다.

#### 2. 도메인 연결은 어떤 플랜부터 되나요?

**A:** 커스텀 도메인 연결(Connect a domain) 기능은 **Builder 플랜($50/월) 이상**부터 지원합니다. Starter 플랜에서는 VibeX가 제공하는 기본 프리뷰 링크만 사용하실 수 있습니다.

#### 3. GitHub 연동은 어느 플랜인가요?

**A:** 코드를 GitHub 저장소와 연동(Github integration)하는 기능 역시 **Builder 플랜($50/월) 이상** 부터 사용하실 수 있습니다.

### J-2 크레딧 차감 및 장애 보상

#### 1. 크레딧은 어디서 차감되나요?

**A:** 에디터에서 프롬프트를 입력하여 AI에게 코드를 새로 생성하거나 기존 코드를 수정(Re-prompting)할 때, 그리고 이미지/3D 에셋 렌더링을 지시할 때 사용량(Token)에 비례하여 크레딧이 차감됩니다.

#### 2. 생성 중단 시 차감되나요?

**A:** 생성 중 네트워크 에러나 타임아웃으로 프로세스가 비정상 중단된 경우, 시스템이 이를 감지하여 해당 작업에 묶여있던 크레딧을 차감하지 않고 돌려줍니다.

#### 3. 생성/배포 실패 시 크레딧은 환불/복구 되나요?

**A:** 'Build Failed'와 같이 명백한 시스템 환경 오류로 인해 렌더링이 실패한 경우, 소모된 크레딧은 약 15분 이내에 고객님의 계정으로 자동 복구(Refund) 처리됩니다.

#### 4. 장애 보상이 있나요?

**A:** VibeX 서버의 대규모 장애(장시간 접속 불가 등)가 발생한 경우, 장애 시간에 비례하여 모든 피해 고객님들의 계정으로 보상 크레딧을 일괄 지급해 드립니다.

#### 5. 남은 크레딧은 어디서 확인하나요?

**A:** 대시보드 우측 상단의 프로필을 클릭하신 후, [계정 및 결제 관리] 메뉴에 들어가시면 이번 달 사용한 크레딧과 남은 잔여 크레딧 게이지를 실시간으로 확인하실 수 있습니다.

#### 6. 크레딧이 이월되나요?

**A:** 아니요, 각 플랜에서 매월 제공되는 기본 크레딧은 결제 주기가 갱신되는 날을 기준으로 초기화되며 다음 달로 이월(Rollover)되지 않습니다.

### J-3 결제 처리 오류

#### 1. 결제가 실패했습니다.

**A:** 등록하신 신용/체크카드의 해외 원화 결제(DCC)가 차단되어 있거나 잔도 한도 부족일 수 있습니다. 카드사에 문의하시거나 다른 결제 수단으로 변경하여 다시 시도해 주세요.

#### 2. 연간 할인 적용이 안 됩니다.

**A:** 요금제 선택 화면 상단의 토글을 '연간 구독(20% 할인)'으로 맞춘 상태에서 플랜을 선택하셔야 할인이 적용됩니다. 월간 구독을 선택하시면 할인이 적용되지 않습니다.

#### 3. 영수증/세금계산서 발급을 받을 수 있나요?

**A:** 네, 결제가 완료되면 계정의 이메일로 인보이스(영수증)가 자동 발송됩니다. 대시보드의 결제 내역 탭에서도 PDF 형태로 직접 다운로드하실 수 있습니다.

### J-4 구독 변경 및 환불

#### 1. 플랜을 업그레이드하면 즉시 적용되나요?

**A:** 네, 하위 플랜에서 상위 플랜으로 업그레이드하실 경우, 남은 기간만큼의 차액이 일할 계산되어 즉시 결제되며 상위 플랜의 기능과 크레딧이 즉각 적용됩니다.

#### 2. 다운그레이드하면 기능이 제한되나요?

**A:** 다운그레이드를 예약하시면 다음 결제 갱신일까지는 현재의 상위 플랜 기능이 유지됩니다. 다음 결제일부터 하위 플랜으로 변경되며 커스텀 도메인 등의 고급 기능 접근이 제한될 수 있습니다.

#### 3. 환불이 가능한가요?

**A:** 결제일로부터 7일 이내이며 지급된 크레딧을 거의 사용하지 않으신 경우(정책상 10% 미만)에 한해 전액 환불이 가능합니다. support@vibe-x.app으로 환불을 요청해 주세요.

#### 4. 해지 후 데이터는 유지되나요?

**A:** 네, 구독(자동 결제)을 해지하시더라도 계정 자체를 탈퇴하지 않는 이상 이미 생성하신 프로젝트와 코드 데이터는 대시보드에 안전하게 유지됩니다.

### J-5 목적별 플랜 추천

#### 1. 사이드 프로젝트에 적합한 플랜은 무엇인가요?

**A:** 코드를 내보내어 개인적으로 테스트하거나 간단히 즐기기 위한 목적이라면, 월 10만 크레딧이 제공되는 **Starter 플랜($20/월)** 이 가장 합리적입니다.

#### 2. 상용 서비스 운영에 적합한 플랜은?

**A:** 실제 유저를 받고 서비스를 운영하시려면 나만의 도메인 연결과 백엔드 기능이 필수적이므로 **Builder 플랜($50/월) 이상** 을 강력히 권장합니다.

#### 3. 교육용으로 저렴한 플랜이 있나요?

**A:** 별도의 교육용 플랜은 제공하지 않으나, 연간 결제를 선택하시면 **Starter 플랜을 20% 할인된 가격(월 $15.33 상당)** 으로 저렴하게 이용하실 수 있습니다.

#### 4. 팀 협업에 적합한 플랜은 무엇인가요?

**A:** 잦은 수정과 많은 크레딧 소모가 예상되는 팀 단위 작업이라면, 월 50만 크레딧이 제공되는 **Pro 플랜** 이나 최우선 기술 지원이 포함된 **Elite 플랜** 을 추천합니다.

## K. 프롬프트 엔지니어링 (Prompting Tips)

### K-1 복잡 기능 구현

#### 1. 관리자 페이지를 포함하려면 어떻게 작성해야 하나요?

**A:** 프롬프트에 "일반 유저 화면 외에, 상품 등록과 회원 관리를 할 수 있는 '관리자 전용 대시보드(Admin Dashboard)' 화면을 분리해서 별도의 라우팅으로 만들어 줘"라고 명확히 지시해야 합니다.

#### 2. DB 구조를 명시하려면 어떻게 요청하나요?

**A:** "이 앱에서 사용할 유저 정보와 게시글 데이터를 정의하는 JSON 형태의 데이터베이스 스키마(Mock Data)를 코드 상단에 구성해 줘"라고 데이터 구조를 콕 집어 요구하세요.

#### 3. 로그인/권한 시스템을 포함하려면?

**A:** 껍데기만 만들어지는 것을 방지하려면 "이메일과 비밀번호 입력 폼을 만들고, '로그인 상태(isLoggedIn)'를 관리하는 React State 로직을 반드시 포함시켜 줘"라고 명시해야 합니다.

#### 4. 결제 기능을 추가하려면 무엇을 적어야 하나요?

**A:** "장바구니에서 결제하기 버튼을 누르면 Stripe 결제 모달이 뜨는 UI 흐름을 만들고, 가상의 결제 성공/실패 Alert 창을 띄우는 함수를 연결해 줘"라고 구체적인 흐름을 적어주세요.

### K-2 디자인 디테일 강제

#### 1. Linear처럼 만들어 달라고 하면 되나요?

**A:** "Linear처럼 만들어줘"와 같은 단어만으로는 부족합니다. "Linear 앱 스타일의 미니멀리즘 테마로, 배경은 아주 어두운 회색(#111111)을 쓰고 테두리에 얇은 1px 반투명 보더(border)를 적용해 줘"라고 구체적인 스타일을 나열하는 것이 좋습니다.

#### 2. 컬러를 정확히 지정하려면 어떻게 하나요?

**A:** "포인트 버튼 색상은 반드시 `#FF5733` HEX 코드를 하드코딩해서 사용하고, 텍스트 색상은 `#FFFFFF`로 지정해 줘"라고 색상 코드를 직접 제공해 주시면 AI가 혼동하지 않습니다.

#### 3. 간격/라운드 값을 명시할 수 있나요?

**A:** 네, "모든 카드 UI의 `border-radius`는 16px로 맞추고, 각 요소 간의 내부 여백(Padding)은 일관되게 24px로 넓게 잡아 줘"라고 CSS 수치를 직접 제시하시면 됩니다.

#### 4. 다국어를 포함하려면 어떻게 작성하나요?

**A:** "UI의 모든 텍스트를 하드코딩하지 말고, i18n 구조를 모방하여 한국어와 영어 문자열 객체를 따로 분리한 뒤 변수로 매핑해 줘"라고 번역 확장을 고려한 코드 구조를 지시하세요.

### K-3 부분 수정 및 디버깅

#### 1. 기존 기능은 유지하고 이것만 수정하려면?

**A:** "기존에 작성된 레이아웃과 로직은 100% 그대로 유지하고, 우측 상단에 알림(Bell) 아이콘만 하나 새로 추가해 줘"라고 이전 상태 보존을 매우 강력하게 명령해야 합니다.

#### 2. Build Failed를 고치려면 어떻게 요청하나요?

**A:** 챗봇에게 단순히 "에러 났어"라고 하기보다는 "패키지 충돌로 Build Failed 에러가 났어. 의존성을 확인하고 문제가 되는 라이브러리 import 구문을 수정해 줘"라고 원인을 함께 제시해 주세요.

#### 3. 에러 로그를 어떻게 첨부해야 하나요?

**A:** 우측 하단의 콘솔(Console) 뷰어에서 붉은색 에러 로그 텍스트를 마우스로 쭉 드래그하여 복사한 뒤, 챗봇 프롬프트 입력창에 그대로 붙여넣고 "이 에러를 고쳐줘"라고 전송하시면 됩니다.

#### 4. 결과가 다를 때 재요청 방법은?

**A:** AI가 엉뚱한 코드를 냈다면 해당 결과물을 무시하고, 좌측 히스토리에서 '되돌리기'를 선택하여 코드를 원상 복구한 뒤, 프롬프트의 지시어를 더 뾰족하고 명확하게 다듬어 다시 전송하세요.

### K-4 외부 환경 보장

#### 1. 특정 프레임워크로 제한할 수 있나요?

**A:** 네, 첫 프롬프트를 작성할 때 "이 프로젝트는 오직 순수 HTML, CSS, Vanilla Javascript만 사용해서 만들어 줘. React나 Tailwind는 절대 쓰지 마"라고 강력한 네거티브 제약을 걸어주시면 됩니다.

#### 2. 테스트 코드를 포함시킬 수 있나요?

**A:** "주요 비즈니스 로직 함수 아래에 Jest 프레임워크 기반의 유닛 테스트 코드 예시를 3개 작성해 줘"라고 지시하시면 테스트 스크립트를 주석이나 별도 파일 형태로 제공해 줍니다.

#### 3. 더미 데이터를 포함해 달라고 요청하려면?

**A:** "화면이 텅 비어 보이지 않도록, 사용자 목록을 렌더링할 때 배열 형태의 가짜(Mock) 더미 데이터 10개를 미리 넣어서 화면을 구성해 줘"라고 요청하세요.

#### 4. 환경변수 없이 동작하게 만들 수 있나요?

**A:** "외부 API를 직접 호출하면 에러가 나니까, 별도의 `.env` 파일이나 API 통신 없이도 프론트엔드 단에서 독립적으로 UI가 작동하도록 임시 하드코딩 데이터를 사용해 줘"라고 명시하시면 됩니다.

## L. 기업 보안 및 시스템 상태 (Security & System)

### L-1 백업 정책

#### 1. 프로젝트 백업이 자동으로 되나요?

**A:** 네, VibeX 에디터 내에서 발생하는 모든 코드 생성과 편집 내역은 백그라운드에서 실시간으로 VibeX 클라우드 서버에 안전하게 자동 저장(백업)됩니다.

#### 2. 백업 주기는 어떻게 되나요?

**A:** 정해진 시간 주기가 아니라, AI를 통해 코드가 생성되거나 사용자가 타이핑하여 변경 사항이 감지되는 '이벤트 발생 시점'마다 버전을 나누어 촘촘하게 저장됩니다.

#### 3. 데이터 복원 요청이 가능한가요?

**A:** 사용자가 직접 프로젝트를 '삭제'한 경우 영구 파기되어 복원이 불가능합니다. 단, 에디터 내부의 '버전 기록(History)'을 통해 최근 작업했던 과거 시점으로 코드를 롤백하는 기능은 제공됩니다.

### L-2 기업 보안 및 법적 요구

#### 1. IP 접근 제한이 가능한가요?

**A:** 회사 사내망 등 특정 IP에서만 프로젝트에 접근할 수 있게 하는 화이트리스트 기능 등은 엔터프라이즈 환경에서 별도 협의를 통해 제공됩니다.

#### 2. 감사 로그/보안 인증을 제공하나요?

**A:** SOC2, GDPR 규정 준수 및 세부적인 워크스페이스 감사 로그(Audit Log) 제공 등 엔터프라이즈 기업을 위한 보안 스펙은 영업팀(Sales) 문의를 통해 안내받으실 수 있습니다.


### L-3 전체 장애 및 점검

#### 1. 지금 서비스에 장애가 있나요? (전체 서비스가 느리거나 로그인이 안 됩니다.)

**A:** 갑자기 접속이 불가하거나 모든 생성이 멈췄다면 전체 서버 장애일 가능성이 높습니다. 최신 서비스 상태는 VibeX 공식 홈페이지 하단의 '상태(Status) 페이지' 링크를 통해 실시간으로 확인하실 수 있습니다.

#### 2. 서버 점검 중인가요? 예정된 점검 일정이 있나요?

**A:** 정기 서버 점검이나 메이저 업데이트가 예정된 경우, 최소 3일 전에 대시보드 상단 배너와 가입하신 계정의 이메일을 통해 점검 시간과 영향을 사전 공지해 드립니다.

#### 3. 최근 업데이트/버전 변경 내역은 어디서 보나요?

**A:** VibeX에 새롭게 추가된 기능(AI 모델 업그레이드, 새 프레임워크 지원 등) 및 버그 수정 내역은 메인 홈페이지의 '릴리즈 노트(Changelog)' 탭에서 상세히 확인하실 수 있습니다.

### L-4 성능 저하

#### 1. 생성 속도가 평소보다 느립니다. (큐 대기 시간이 길어졌습니다.)

**A:** 전 세계적으로 사용자가 동시에 몰리는 트래픽 피크 타임이거나, 대규모 백엔드 작업이 진행 중일 때 AI 요청 큐(Queue) 대기열이 길어지면서 일시적인 지연이 발생할 수 있습니다.

#### 2. 특정 시간대에만 느리고 배포가 지연됩니다.

**A:** 특정 국가의 업무 시작 시간 등에 트래픽이 몰리는 병목 현상입니다. 만약 배포나 이미지 에셋 로딩이 비정상적으로 느리다면 글로벌 CDN 서버의 응답 문제일 수 있으니 잠시 후 다시 시도해 주시기 바랍니다.
