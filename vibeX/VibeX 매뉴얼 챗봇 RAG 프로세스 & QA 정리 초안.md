# VibeX 매뉴얼 챗봇 RAG 프로세스 1차 정리 및 QA


## 1. 목적
VibeX 매뉴얼 기반 RAG(Retrieval-Augmented Generation) 아키텍처 구조를 정의 하고, 챗봇의 배포 및 QA를 하기 위해 참고용으로 작성된 문서입니다.


<br>
<br>


## 2. 전체 아키텍처 개요
VibeX 매뉴얼 챗봇은 RAG 구조 기반으로 구성되며, 전체 흐름은 다음과 같습니다.


```
문서 업로드 → 텍스트 추출/분할 → 임베딩 생성 → 벡터 저장(Qdrant)
→ 사용자 질의 → 벡터 검색 → Claude 4.5 응답 생성
```


<br>
<br>

### 2.1 시스템 구성 요소 및 역할
|**구분**|**구성 요소**|**역할**|
|---|---|---|
|**문서 업로드**|`DocumentController`|매뉴얼 파일(PDF, TXT) 업로드 및 파이프라인 시작|
|**텍스트 추출**|`Apache Tika`|업로드된 문서에서 순수 텍스트 추출|
|**텍스트 분할**|`LangChain4j`|긴 텍스트를 약 1,000자 단위(Chunk)로 분리|
|**벡터 저장소**|`Qdrant`|벡터 및 메타데이터 저장, 코사인 유사도 기반 검색|
|**질의 처리**|`ChatService`|질문 처리, 벡터 검색 요청 및 프롬프트 구성|
|**LLM**|`Claude 4.5`|검색된 매뉴얼 Context 기반 최종 답변 생성|

<br>
<br>

### 2.2 동작 프로세스
- **1단계 (문서 업로드):** VibeX 사용법, 기술 명세, UI 가이드라인 등 사내 매뉴얼 원본 파일(PDF, TXT)을 시스템에 업로드합니다.
    
- **2단계 (데이터 정제):** 업로드된 긴 문서를 AI가 정확하게 인식할 수 있도록 약 1,000자 단위의 의미 있는 단락으로 분할합니다. (Tika, LangChain4j 활용)
    
- **3단계 (지식 DB 구축):** 분할된 매뉴얼 데이터를 벡터(숫자) 형태로 변환하여 전용 데이터베이스(Qdrant)에 저장합니다.
    
- **4단계 (AI 질의응답):** 사용자가 질문하면(예: "버튼 색상 규정 알려줘"), DB에서 가장 정확한 매뉴얼 내용을 찾아 AI(Claude 4.5)가 사용자 친화적인 답변을 제공합니다.

<br>
<br>

### 2.3 시스템 플로우 차트(System Flowchart)
- 아래 흐름도는 VibeX 매뉴얼 챗봇이 지식을 학습하고 답변을 도출하는 전체 과정을 '사전 데이터 준비' 와 '실시간 질의응답' 두 단계로 나누어 보여줍니다.
``` mermaid
%%{init: {'theme': 'base', 'themeVariables': { 'primaryColor': '#E1F5FE', 'edgeLabelBackground':'#ffffff', 'tertiaryColor': '#F0F4C3'}}}%%
graph TD
    subgraph " 데이터 준비 파이프라인 (In-advance)"
        A[관리자<br/>VibeX 매뉴얼 PDF/TXT] -->|파일 업로드| B(DocumentController);
        B --> C{Apache Tika<br/>+<br/>LangChain4j};
        C -->|텍스트 추출 및<br/>1000자 단위 분할| D[텍스트 Chunks];
        D -->|Embedding<br/>벡터 변환| E[(Qdrant<br/>벡터 DB)];
    end

    subgraph " 실시간 질의응답 파이프라인 (Real-time)"
        F[사용자] -->|버튼 색상 규정 알려줘| G(ChatService);
        G -->|질문 벡터화| E;
        E -->|유사도 검색 결과<br/>Top-K Chunks 반환| G;
        G -->|프롬프트 구성<br/>질문 + 관련 Chunks| H[Claude 4.5<br/>LLM];
        H -->|매뉴얼 기반<br/>답변 생성| G;
        G -->|최종 답변 출력| F;
    end

    style E fill:#FFF9C4,stroke:#FBC02D,stroke-width:2px
    style H fill:#E1BEE7,stroke:#8E24AA,stroke-width:2px
```
- **1. 사전 데이터 준비 파이프라인**
    - **동작:** 관리자가 VibeX 매뉴얼(PDF, TXT)을 시스템에 업로드하면, 내부적으로 문서를 텍스트로 추출하고 AI가 소화하기 좋은 1,000자 단위(Chunk)로 쪼갭니다.
    - **목적:** 쪼개진 텍스트를 수치화(벡터화)하여 `Qdrant` DB에 미리 저장해 둠으로써, 챗봇 전용 **'사내 지식 창고'를 사전에 구축**합니다.
        
- **2. 실시간 질의응답 파이프라인 (Real-time)**
    - **동작:** 사용자가 챗봇에 질문(예: "버튼 색상 규정 알려줘")을 입력하면, 시스템은 즉시 질문을 분석하여 `Qdrant` DB에서 가장 관련성 높은 매뉴얼 조각(Top-K)을 찾아냅니다.
    - **목적:** 찾아낸 매뉴얼 조각을 `Claude 4.5`에게 참고 자료(Context)로 전달하여, **오직 매뉴얼에 기반한 정확하고 신속한 답변을 생성**하여 사용자에게 제공합니다.

<br>

### 2.4 전체 시스템 동작 시퀀스 다이어그램 (Sequence Diagram)
- 아래 시퀀스 다이어그램은 사용자가 챗봇에 질문을 입력한 순간부터 최종 답변을 받기까지, 시스템 내부(`ChatService`)에서 데이터가 처리되는 과정을 시간 순서대로 보여줍니다.

``` mermaid
sequenceDiagram
    participant User
    participant ChatService
    participant Qdrant
    participant Claude

    User->>ChatService: 질문 입력
    ChatService->>ChatService: 질문 Embedding 생성
    ChatService->>Qdrant: 유사도 검색 요청
    Qdrant-->>ChatService: Top-K 문서 반환
    ChatService->>Claude: Context + 질문 전달
    Claude-->>ChatService: 답변 생성
    ChatService-->>User: 최종 응답 반환

```
- **1. 질문 입력 및 벡터화 (Embedding)** 
    - 사용자가 챗봇에 질문(예: "버튼 색상 규정 알려줘")을 입력하면 `ChatService`가 이를 수신합니다.
    - 수신된 텍스트 질문을 시스템이 검색할 수 있도록 의미를 담은 숫자 형태(벡터)로 변환합니다.
        
- **2. 매뉴얼 기반 유사도 검색 (Qdrant)**
    - 벡터화된 질문을 `Qdrant`(벡터 DB)에 보내어, 사전에 업로드해 둔 VibeX 매뉴얼 데이터 중 질문의 의도와 가장 유사한 텍스트 조각(Chunk) 상위 K개(Top-K)를 검색하여 가져옵니다.
        
- **3. 프롬프트 구성 및 답변 생성 (Claude 4.5)**
    - **[RAG의 핵심]** DB에서 찾은 '정확한 매뉴얼 원본 내용(Context)'과 '사용자의 원래 질문'을 하나로 묶어 `Claude 4.5` 모델에 전달합니다.
    - 이를 통해 AI가 임의로 지어내지 않고(환각 방지), 오직 전달받은 매뉴얼 내용만을 근거로 삼아 신뢰도 높은 답변을 생성합니다.
        
- **4. 최종 응답 반환**
    - 생성된 매뉴얼 기반의 답변을 최종적으로 사용자 화면에 출력하여 질의응답을 종료합니다.

## 3. QA 점검 체크리스트(참고용)

- 아래 체크리스트는 단순 참고용으로 해당 기능의 구현에 있어서 보편적인 오류 사항의 점검을 위한 체크리스트로 작성되었습니다. 

### 3.1 문서 처리 및 적재 파이프라인 검증 (Ingestion & DB)

- 사용자가 아닌 **관리자(시스템) 관점**에서 매뉴얼이 정상적으로 쪼개져 DB에 들어가는지 확인합니다.

- [ ] **업로드 및 추출 (Tika):** VibeX 매뉴얼(PDF, TXT) 업로드 시 서버 에러(Timeout 등) 없이 처리되는가?
- [ ] **인코딩 확인:** 추출된 텍스트에서 한글 깨짐이나 특수문자, 표/목차 데이터의 심각한 훼손이 없는가?
- [ ] **분할 단위 검증 (LangChain4j):** 1,000자 단위 Chunk가 문장 중간이나 단어 중간에서 억지로 끊기지 않고, 문맥을 어느 정도 유지하며 분할되는가?
- [ ] **중복 방지 (Qdrant):** 동일한 매뉴얼을 두 번 업로드했을 때, 벡터 DB에 데이터가 중복으로 쌓이지 않고 덮어쓰기(또는 무시) 처리되는가?

<br>

### 3.2 검색 정확도 및 LLM 응답 품질 검증 (Retrieval & Generation)

- **사용자 관점**에서 질문했을 때, 엉뚱한 문서를 찾거나 거짓말(환각)을 하지 않는지 확인합니다.

- [ ] **검색 정확도 (Qdrant Top-K):** "버튼 색상 규정" 질문 시, 엉뚱한 Chunk가 아닌 실제 'UI 가이드라인' Chunk를 Top-K로 잘 가져오는가?
- [ ] **유사어/동의어 처리:** "버튼 컬러 알려줘" (색상 -> 컬러) 처럼 단어가 조금 달라도 의도를 파악해 동일한 문서를 검색해 내는가?
- [ ] **환각(Hallucination) 통제:** 매뉴얼에 아예 없는 내용(예: "VibeX의 점심 메뉴 추천")을 물어봤을 때, 지어내지 않고 "매뉴얼에 해당 내용이 없습니다"라고 방어할 수 있는가? (Claude 4.5 프롬프트 검증)
- [ ] **출처 신뢰성:** 답변 시, Claude가 참조한 매뉴얼의 이름이나 파트를 정확히 근거로 삼아 대답하는가?
    
<br>

### 3.3 예외 상황 및 UX(사용자 경험) 검증

- 실제 서비스 운영 시 발생할 수 있는 짜증 나는 상황(Edge Case)들을 점검합니다.

- [ ] **응답 지연 시간(Latency):** 사용자가 질문한 후 최종 답변이 나오기까지의 시간이 너무 오래 걸리지 않는가? (권장 3~5초 이내)
- [ ] **모호한 질문 대응:** "버튼 어떻게 해?" 처럼 너무 짧거나 모호한 질문 시, 되묻거나 관련 목차를 제시하도록 유도되는가?
- [ ] **에러 메시지 처리:** DB 연결 실패, LLM API 호출 실패 등의 시스템 에러 발생 시, 사용자에게 날 것의 에러 코드 대신 친절한 시스템 안내 메시지가 노출되는가?
