## 1. 프롬프트 아키텍처 및 평가 투명성 고도화

- **평가 근거 선행(Rationale-First) 스키마 적용:** 점수 산정 이전에 반드시 상용화 기준의 결함과 구체적인 물리적 증거(코드 발췌)를 먼저 작성하도록 JSON 스키마의 순서를 강제함. 이를 통해 인공지능이 무비판적으로 높은 점수를 먼저 부여한 뒤 억지로 이유를 지어내는 환각(Hallucination) 현상을 원천 차단함.
    
- **채점 이력 및 근거 데이터 영구 보존:** 다중 반복(Iteration) 채점 시 도출된 감점 요인과 칭찬 증거들을 단순 폐기하지 않고 병합 및 중복 제거하여 최종 데이터에 보존함. 평가 결과에 대한 명확한 추적성을 확보하여 벤치마크의 투명성을 대폭 강화함.

## 2. 코드 복잡도 산출 및 필터링 무결성 확보

- **대용량 코드 분석 제한 해제:** 파일 읽기 시 적용되던 최대 12,000자 제한을 5,000,000자로 대폭 확장함. 이로써 단일 파일이 거대한 대규모 프로젝트에서도 코드 총량이 축소 계산되어 생산성 점수가 부당하게 깎이는 치명적 오류를 교정함.
    
- **목적별 이원화 필터링 및 동적 예외 허용:** 설정 파일(`package-lock.json` 등)과 전체 용량에 큰 영향을 미치는 범용 UI 라이브러리를 제외하여 '순수 비즈니스 로직'만을 평가 모수로 추출함. 단, 사용자 프롬프트에 UI나 컴포넌트 수정과 관련된 키워드가 감지될 경우, 해당 배제 필터를 자동으로 해제하여 평가의 사각지대를 없앰.

## 3. 생성 효율(GenEfficiency) 평가식의 전면 개편

인공지능의 부정확한 시간 추론에 의존하던 방식을 폐기하고, 백엔드 서버에서 추출된 '순수 코드 길이'와 '초 단위 소요 시간'을 바탕으로 3단계 수학적 연산을 직접 수행함. (소요 시간이 누락되는 예외 상황 발생 시 통계 붕괴를 막기 위해 기본 1.0점을 할당함)

- **Step 1. 복잡도($C$) 산출 및 동적 상한선 확장:** 불필요하게 코드를 길게 작성하는 꼼수를 막기 위해 과제 난이도별 적정 코드량 상한선(L1: 2.5만, L2: 8만, L3: 15만 자)을 적용함. 단, 기능과 화면 깊이 점수가 모두 4.0 이상인 고품질 산출물에 한해서는 한도를 최대 2배까지 동적으로 확장해 주어 명품 코드를 정당하게 보상함.
    
    $$C = \frac{\min(\text{Pure Code Length}, \text{Dynamic Cap})}{10,000}$$
    
- **Step 2. 난이도 보정 효율($E$) 계산:** 산출된 복잡도($C$)에 난이도별 가중치($W$)를 곱하고 생성 소요 시간으로 나누어 초당 실질 생산성 지표($E$)를 산출함. 결제나 인증 등 복잡한 워크플로우를 요하는 과제일수록 높은 가중치가 부여됨.
    
    $$E = \frac{C \times W}{\text{Generation Time (seconds)}}$$
    
- **Step 3. 절대 평가 점수 맵핑:** 산출된 효율성 지표($E$)를 L1, L2, L3 난이도별로 세분화된 커트라인에 대입하여 최종 점수를 확정함.
    

|**최종 점수**|**L1 컷 (완화)**|**L2 컷 (기본)**|**L3 컷 (엄격/분리)**|
|---|---|---|---|
|**5.0점**|$E \ge 0.0080$|$E \ge 0.055$|$E \ge 0.070$|
|**4.0점**|$E \ge 0.0060$|$E \ge 0.040$|$E \ge 0.050$|
|**3.0점**|$E \ge 0.0045$|$E \ge 0.030$|$E \ge 0.038$|
|**2.0점**|$E \ge 0.0035$|$E \ge 0.020$|$E \ge 0.026$|
|**1.0점**|$E < 0.0035$|$E < 0.020$|$E < 0.026$|

## 4. 통계적 신뢰성 및 실제 구동 검증 도입

- **통계적 점수 보정 (베이지안 수축):** 추출된 코드 길이, 유효 파일 수, 테스트 반복 횟수를 종합하여 증거량이 통계적으로 부족할수록 산출 점수를 기본값(3.0)에 가깝게 하향 보정함. 단, 길이가 짧더라도 인공지능이 명시적인 물리적 증거 코드를 찾아냈다면 보정 패널티를 전면 면제하여 '최적화된 짧은 코드'를 보호함.
    
- **실제 구동 환경(Runtime) 교차 검증:** 웹 자동화 도구(Playwright)를 활용해 배포된 URL의 정상 접속 여부, 콘솔 및 페이지 에러, CTA 버튼 클릭 시 정상 라우팅 여부를 런타임에 동적 검증함. (새 창 열림 속성으로 인한 검증 정체 현상 방지 로직 포함)
    
- **최종 점수 안전장치 (Guardrails):** 실제 앱 구동이 실패하거나 핵심 런타임 에러가 발견될 경우, 백엔드 로직이 강제로 개입하여 기능 점수 등을 최대 2.0~3.0점으로 삭감함. 또한, 화면 깊이가 과제 요구 수준에 미치지 못하면 효율성 점수를 최대 4.0점까지만 인정하여 벤치마크의 신뢰도를 유지함.
